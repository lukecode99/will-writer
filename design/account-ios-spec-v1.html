Design decisions

1. Sign-in mechanism

Ship v1: Option A — 6-digit email OTP Hold v2: Option B — Universal Link
A — 6-digit OTP (recommended) ✓ B — Universal Link
How it works Server emails 6 digits. User switches to Mail, reads code, returns to app, types code in State B. App POSTs to /auth/otp/verify, receives session token. Server emails a ?login=<token> link. User taps it; iOS reads the app's Associated Domains entitlement and opens SortedWill with the token in the URL.
New server routes POST /api/v1/auth/otp/request
POST /api/v1/auth/otp/verify		 Same two routes, but email body changes from code to link. Plus: host AASA JSON at /.well-known/apple-app-site-association.
New app work OTP entry screen (States B/B-err). No entitlements. Works on Expo Go and simulator. Add Associated Domains entitlement (applinks:sortedwill.com). Handle Linking.addEventListener in root navigator. Requires signed EAS build — not simulator.
Failure modes Code spam-filtered or expired: user taps Resend. App-side only. If AASA unreachable or malformed, iOS falls back to Safari — session token leaks to browser history. Cold-start race may miss the deep-link event.
UX friction One extra step: switch to Mail, read code, type. Familiar and trusted for UK users. iOS may autofill the code from the notification. Lower friction: one tap in Mail. Requires app installed and AASA correct.
Implementation notes for Nano:
  • POST /api/v1/auth/otp/request — accepts { email }, generates a 6-digit code (HMAC-TOTP or random, 15-min TTL, store hash server-side), sends email. Same non-disclosing response whether account exists: { ok: true } — same behaviour as the web magic-link path.
  • POST /api/v1/auth/otp/verify — accepts { email, code }, validates hash. Returns { token: "…" } on success or { error: "invalid_code" } on failure. Rate-limit: 5 attempts per email per 10 min.
  • OTP State B auto-submits when the 6th digit is entered. On invalid_code: clear all 6 boxes, show B-err error message, focus box 1. Re-enable Resend immediately.
  • Resend cooldown: 60 s. Show "Resend in 44s" (link-btn dimmed) during cooldown, then re-enable "Resend code". Include SMS-style subject line hint to help iOS Keyboard autofill: "Your SortedWill code is 371294".
  • The existing requestLogin(email) in print.ts sends the web magic link; the iOS OTP is a separate call. Web flow unchanged.

2. Session token storage

Ship: iOS Keychain via expo-secure-store

AsyncStorage is unencrypted and included in iCloud/iTunes backups. The session token must live in the iOS Keychain — encrypted at rest, iCloud-excluded by default, wiped on app uninstall.

Use expo-secure-store (standard Expo package, no native build needed):
  • Write on sign-in: await SecureStore.setItemAsync('sw_session_token', token)
  • Read on app launch: const token = await SecureStore.getItemAsync('sw_session_token')
  • Delete on sign-out or 401: await SecureStore.deleteItemAsync('sw_session_token')
Default Keychain accessibility is kSecAttrAccessibleWhenUnlockedThisDeviceOnly — does not migrate via iCloud Keychain (correct: session tokens shouldn't cross devices; user re-authenticates on a new device). No change needed unless cross-device token persistence is ever wanted.

3. iCloud / iTunes backup posture

Ship: Exclude will store from backup (not opt-in)

Will content lives in an on-device SQLite database. Files in Expo's documentDirectory ride iCloud and iTunes backups by default — which breaks "your answers never leave this device" at the OS level. Recommendation: exclude unconditionally. Making it opt-in creates a path that quietly contradicts the product's core privacy promise.

Preferred (expo-file-system ≥ v18): one call after the DB is first opened:
  • await FileSystem.setIsExcludedFromBackup(dbUri, true)
If expo-file-system < v18:
  • Config plugin (cleanest): a small Expo config plugin (~20 lines) sets NSURLIsExcludedFromBackupKey=true on the DB directory at build time. Persistent; survives app updates.
  • Native bridge (pragmatic): call NSURL.setResourceValues via a one-off native module on first launch. Requires a custom dev client, not Expo Go.
The session token (Decision 2) is already excluded from backup by iOS Keychain — no extra work there.

Nano to check: which expo-file-system version is in the project. If ≥ 18, one liner. If not, flag and I'll scope the config plugin.

4. Privacy copy — iOS parity + one addition

Ship: Web copy unchanged + one iOS sentence in State C card

Web copy is already clear and factually accurate. iOS copy matches exactly. One sentence is added to the signed-in card to address the iOS backup question proactively — a user who knows about iCloud will otherwise wonder.

State A — below "Send code" button (exact web copy, word-for-word):

5. Account button tap target — fix (self-review item, ship now)

Ship: paddingVertical 7 → 11 in AppHeader.tsx

The Account button in AppHeader currently has paddingVertical: 7, giving ~31 px height. iOS HIG minimum is 44 px. Same applies to "Use a different email" and "Resend code" in the OTP states.

In AppHeader.tsx styles.accountBtn: paddingVertical: 7 → 11 (11 + 11 + ~13 line-height ≈ 44 px).

In OTP States B/B-err:
  • "Resend code" / "Resend in Ns": wrap touchable in minHeight: 44
  • "Use a different email": same
This change is in the shared AppHeader — benefits all screens. Net visible change: ~4 px taller button at the right edge of the header; unnoticeable at normal viewing distance.

6. Signed-in identity indicator in AppHeader (self-review item)

Ship: Email initial in Account button when signed in

Currently "Account" looks identical signed-in and signed-out. The signed-in state should signal the persisted session at a glance.

When accountActive and a session is present, render a 20 × 20 circle containing the user's email initial inside the Account button (see State C mock). AppHeader needs access to the initial:
  • Add optional prop accountInitial?: string to AppHeader
  • When provided and accountActive: render the circle left of "Account" text
  • Circle style: { width: 20, height: 20, borderRadius: 10, backgroundColor: C.primary, alignItems: 'center', justifyContent: 'center' } — initial text: white, 10 px, 700
Derive the initial from account.email[0].toUpperCase().
